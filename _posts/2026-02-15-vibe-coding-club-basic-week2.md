첫 실습에서 알림 자동화를 20분 만에 끝내겠다고 했다가, 웹훅 주소 한 줄을 잘못 넣어 전송이 전부 실패했다. 반복 업무를 줄이려던 시도가 오히려 수작업 복구로 돌아온 순간이었다. 그래서 2주차는 “일단 연결”이 아니라 워크플로우를 설계하는 순서부터 다시 잡았다.

No Code 자동화 도구를 쓰면 코딩 비중을 크게 줄인 채 반복 업무를 묶어낼 수 있고, 이번 주의 중심 도구는 **n8n**이었다. 이 배경을 이해하면 왜 먼저 No Code 자동화의 정의부터 짚는지 자연스럽게 연결된다.

---

## No Code 자동화란

No Code 자동화는 코드를 거의 쓰지 않고 반복 업무를 연결하는 방식이다. 화면에서 노드를 이어 붙여 트리거와 액션을 정하면, 사람이 매번 클릭하던 작업을 자동으로 돌릴 수 있다.

예를 들면 바로 이런 식이다.

- 오전 9시에 뉴스 RSS 5개를 읽고 슬랙 채널에 3줄 요약 전송
- 고객 메일 제목에 "환불"이 들어오면 시트에 자동 기록 후 담당자 멘션
- 디스코드 웹훅으로 배포 실패 로그를 즉시 알림

처음엔 "No Code면 코드를 한 줄도 안 쓴다"고 생각했다. 근데 날짜 포맷 변경과 조건 분기에서 막혔다. 다시 해보니 Function 노드에 짧은 JavaScript 6줄을 넣는 순간 원하는 자동화가 바로 돌아갔다.

내가 실제로 틀렸던 이해: "No Code 도구는 복잡한 업무에는 못 쓴다."
수정된 이해: "80%는 UI로 만들고, 막히는 20%만 짧은 코드로 보완하면 실무 자동화가 충분히 가능하다."

### No Code 자동화 도구 3대장

대표적인 도구 세 가지를 비교해보자.

| 도구                  | 특징                                           | 가격                   |
| --------------------- | ---------------------------------------------- | ---------------------- |
| **Zapier**            | 가장 대중적. 사용이 쉽고 연동 서비스가 많다    | 유료 중심              |
| **Make (Integromat)** | 시각적 워크플로우가 직관적. 복잡한 로직도 가능 | 프리미엄 모델          |
| **n8n**               | 오픈소스. 셀프 호스팅 가능. 가성비 최고        | **무료 (셀프 호스팅)** |

n8n의 최대 장점은 **셀프 호스팅하면 평생 무료**라는 점이다. Docker로 내 컴퓨터에 설치하면 비용 걱정 없이 자유롭게 사용할 수 있다.

## Docker 설치하기

n8n을 로컬에서 돌리려면 먼저 Docker가 필요하다.

### 1. Docker Desktop 다운로드

[Docker 공식 다운로드 사이트](https://www.docker.com/products/docker-desktop/)에서 본인 운영체제에 맞게 다운로드한다.

- **Mac (Apple Chip)**: M1, M2, M3 등 최신 맥북
- **Mac (Intel Chip)**: 구형 맥북
- **Windows**: 윈도우 사용자

### 2. 설치 진행

**Windows 사용자:**

1. 다운로드한 `Docker Desktop Installer.exe` 실행
2. "Use WSL 2 instead of Hyper-V" 체크박스가 있다면 체크된 상태(권장)로 두고 Ok
3. 설치 완료 후 Close (재부팅 필요 시 재부팅)

> WSL2 오류가 뜬다면? "WSL 2 installation is incomplete" 에러가 나올 수 있다. 터미널에서 `wsl --update` 명령어로 해결된다.

**Mac 사용자:**

1. 다운로드한 `.dmg` 파일 실행
2. Docker 아이콘을 Applications 폴더로 드래그
3. Applications에서 Docker 실행

### 3. 설치 확인

설치 후 Service Agreement(이용 약관)에서 Accept를 누르면 된다. 로그인 화면이 나오는데, 개인 사용자는 **'Continue without signing in'**으로 넘어가도 무방하다.

좌측 하단에 **초록색 'Engine running'**이 뜨면 Docker가 정상 작동하는 것이다.

터미널에서 최종 확인:

```bash
docker -v
```

`Docker version 29.x.x...` 같은 버전 정보가 나오면 설치 완료다.

## n8n 설치 및 실행

Docker가 준비되었으면 n8n을 설치한다.

### Docker Hub에서 n8n 다운로드

Docker Desktop의 왼쪽 패널에서 Docker Hub를 열고 "n8n"을 검색한다. `n8nio/n8n` 이미지를 찾아서 **Pull** 버튼을 누르면 다운로드가 시작된다.

다운로드가 완료되면 Docker Desktop의 **Images** 탭에서 `n8nio/n8n` 이미지가 표시된다.

### n8n 실행

Images 탭에서 n8n 이미지를 선택하고 **Run**을 클릭하면 n8n이 실행된다. 브라우저에서 `http://localhost:5678`로 접속하면 n8n 대시보드가 나타난다.

터미널에서 직접 실행할 수도 있다.

```bash
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  n8nio/n8n
```

## n8n에 익숙해지기

n8n의 기본 구성 요소를 알아보자.

### 노드(Node)란

n8n에서 모든 작업 단위를 **노드**라고 부른다. 각 노드는 하나의 기능을 담당하고, 노드들을 연결하면 워크플로우가 된다.

주요 노드 종류:

- **Trigger 노드**: 워크플로우를 시작하는 트리거 (스케줄, 웹훅, 이벤트 등)
- **Action 노드**: 실제 작업을 수행 (이메일 전송, API 호출, 데이터 처리 등)
- **연동 노드**: 외부 서비스와 연결 (Telegram, Discord, Email, Slack 등)

### 간단한 실전 예제

n8n에서 바로 만들어볼 수 있는 워크플로우 예제들이다.

**예제 1: 디스코드 웹훅 알림**

Discord 웹훅 URL을 설정하고, 특정 조건이 충족되면 자동으로 디스코드 채널에 메시지를 보내는 워크플로우다.

**예제 2: 이메일 자동 처리**

이메일 수신 트리거 → 내용 분석 → 스프레드시트에 기록하는 파이프라인을 만들 수 있다.

**예제 3: Telegram 봇 연동**

Telegram 봇을 통해 메시지를 받으면 자동으로 응답하거나, 다른 서비스로 전달하는 워크플로우를 구성할 수 있다.

실습에서는 위 예제의 워크플로우를 화면에서 보면서 그대로 따라 만들어보는 방식으로 진행되었다. 옵션 입력 없이 기본 노드들을 연결하는 것만으로도 자동화의 감을 잡을 수 있다.

## 2주차를 마치며

이번 주는 이론보다 손이 먼저 기억한 수업이었다. Docker랑 n8n을 처음 띄울 때는 설치 단계가 전부일 줄 알았는데, 실제로는 "어떤 트리거로 시작해서 어디서 실패를 감지할지"를 먼저 정하는 게 더 중요했다. 자동화는 버튼 몇 번으로 끝나는 작업이 아니라 흐름을 설계하는 일이라는 걸 확실히 느꼈다.

실제 수업 중 놀랐던 점은, 아주 단순한 알림 워크플로우도 예외 상황 하나만 추가하면 구조가 금방 복잡해진다는 사실이었다. 반대로 가장 헷갈렸던 건 노드 간 데이터가 어떻게 전달되는지였다. 화면에서는 연결선 하나인데, 안에서는 JSON 필드가 계속 바뀌어서 중간 확인을 안 하면 금방 길을 잃는다.

그래도 한 번 전체 흐름을 끝까지 돌려보니 "자동화는 거창한 프로젝트"라는 막연한 거리감이 줄었다. 작은 반복 작업부터 붙이면 충분히 실무에 바로 쓸 수 있겠다는 확신이 생겼다.

다음 시간엔 내가 매주 반복하는 보고 알림부터 n8n으로 먼저 옮기고, 실패 로그 처리 방식까지 같이 비교해볼 예정이다.
